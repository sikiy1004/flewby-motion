# ig-pipeline — Claude Code へのルール

Instagram「美容×ガジェット」アフィリエイトアカウントの投稿制作リポジトリ。
- **描画エンジン**（既存）：`data/products.json` + `data/posts/*.json` → `npm run build` → `out/`
- **リサーチ層**：調査 → 投稿案 → **オーナーの承認** → 原稿データ（`research/`、`pipeline/research/`）
- 詳細は README.md と docs/research-layer-plan.md。オーナーとは日本語で話す。

## 絶対に守ること
1. **承認を代行しない**：`npm run research:approve` はオーナーだけが端末で実行する。Claude は実行しない・迂回しない
   （擬似端末・承認ファイルの手書き・ハッシュの書き換えも禁止）。承認後に案を書き換えたら、承認し直してもらう。
2. **リサーチから描画まで無人で一気に進めない**。`/research` は投稿案の提示で止まる。描画（`npm run build`）は
   オーナーの指示があったときだけ。
3. **出典のない数値を使わない**：価格・スペックの数値は、実際に読んだページの URL と取得日時（日本時間）を出典ファイルに
   記録してから使う。不明なら空欄のままにし、推測で埋めない。取得日時は `node -e 'import("./pipeline/research/lib.mjs").then(m=>console.log(m.jstIso()))'` で得る。
4. **使っていない商品の感想・レビューを書かない**。紹介は公式情報と仕様に基づく表現だけ。メーカー公式の表現を使うときは
   「」で囲んで引用と分かる形にし、引用元を記録する。
5. **効能を断定しない**（薬機法・景表法）。`research/compliance.json` のルールに通らない表現は書き直す。ルールを緩めて通さない。
6. **期限切れのセール価格、取得から72時間を超えた価格で投稿案を作らない**（チェックが止める。止まったら再取得する）。
7. **既存スキーマ（`data/schema/`）・描画テンプレート・デザイントークン・世界観（A案／B案）を変えない**。変更が必要なら理由を
   示してオーナーの承認を得る。トレンドの調査結果でデザインを変えない。
8. **API キーをコードや出力に書かない**（`.env` で管理）。商品画像は自分の写真か使用許諾のある画像だけを公開に使う
   （楽天などの画像はレイアウト確認用 `placeholder`）。
9. **規約に反する自動収集をしない**：Amazon は自動取得しない（当面は楽天の価格のみ）。Instagram の競合投稿は、オーナーが
   見て貼った公開情報だけを扱う。公式ページは少量を読むだけにする。

## よく使うコマンド
- `/research [テーマ]` — リサーチして投稿案リストを作り、オーナーに提示して止まる
- `/research-draft <案ID>` — 承認済みの案から原稿データを作ってチェックし、取り込むか確認する
- `/competitor-log` — オーナーが貼った競合の公開投稿から「型」を分類して記録（本文は保存しない）
- `npm run research:sample` / `-- --clean` — テスト用データで流れを試す／片付ける
