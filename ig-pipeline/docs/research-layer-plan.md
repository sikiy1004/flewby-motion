## 0. 既存スキーマへの準拠（変更なし）

リサーチ層は、次の制約をすべて満たすデータだけを出力する（出力前に既存の `pipeline/validate.mjs` で検証する）。

| 対象 | 制約（既存の定義どおり） |
|---|---|
| 商品 `product.schema.json` | 追加項目は不可。必須：id・category・brand・name・price（整数・税込）・image（ローカルのパス）・specs（文字列で6項目まで）・points（1〜3個、各20字まで） |
| 投稿 `post.schema.json` | 追加項目は不可。`cover.word` は英字のみ9字まで、`lead` は50字まで、`aurora` は6種から選択、`products` は1〜4件、`reel.headline` は30字まで、`hashtags` は `#` から始める、`priceDate` は自由入力の文字列 |
| CSV `pipeline/csv.mjs` | 既存の列定義（商品：spec1〜6 / point1〜3 など、投稿：22列）で書き出す |

### スキーマで表現できない要件と、その扱い（提案A：スキーマは変えない）

| 要件 | 扱い |
|---|---|
| 数値ごとの取得元URLと取得日時 | **出典ファイル**（`research/runs/<実行ID>/evidence/<商品ID>.json`）に、項目ごとに記録する。描画エンジンは読まない |
| 通常価格とセール価格の区別、セール期間 | `price` には表示する価格（セール中ならセール価格）を入れる。通常価格・セール価格・期間・取得日時は出典ファイルに記録する。画像とキャプションの注記には、既存の自由入力欄 `priceDate` を使う。例：`2026-11-19 14:00（楽天スーパーSALE価格・12/11 01:59まで）` → 「価格は2026-11-19 14:00（楽天スーパーSALE価格・12/11 01:59まで）時点の参考価格（税込）です。」 |
| 商品画像の取得元URL | 出典ファイルに記録する（`image` はローカルのパスのまま） |
| キャプション案・ハッシュタグ案 | 既存の項目（`cover.lead`・`points`・`hashtags`）を埋めて、既存のキャプション定型で生成し、案として提示する |
| 公式表現の引用 | `points` に入れる場合は「」で囲み、出典ファイルに引用元を記録する。キャプションでは「（メーカー公式より）」と明記する |

**提案A で承認が必要な、スキーマ以外の小さな変更**

- A-1：キャプション定型（`captions/caption.njk`）と `tokens.brand` に、次の1行を追加する。
  「※紹介内容はメーカー公式情報・仕様に基づきます（使用レビューではありません）」
- A-2：サンプルデータにある使用感の表現（`reel.sub`「3年使い比べた結論」など）を、公式情報に基づく表現に修正する。
- A-3：期限切れ価格のチェックは、リサーチ層の検査コマンドで行う（描画エンジンには手を入れない）。

（提案B：出典を正式に持たせたい場合は、任意項目 `sources` / `priceInfo` / `imageSource` をスキーマに追加する。描画には影響しない。）

## 1. 技術選定

| 対象 | 方式 |
|---|---|
| 進行と Web 調査 | **Claude Code のプロジェクトスキル**（`/research`・`/research-draft`）。Web 検索と公式ページの閲読は Claude が行い、API・検証・ファイル生成は Node のスクリプトで行う |
| 楽天市場 | 公式 API：商品検索 `https://openapi.rakuten.co.jp/ichibams/api/IchibaItem/Search/20260701`、ランキング `…/ichibaranking/api/IchibaItem/Ranking/20220601`、ジャンル検索（カテゴリIDの特定用）。認証は `applicationId` と `accessKey`（ヘッダーとクエリのどちらでも可）で、`.env` で管理する。**Referer の要否とセール関連の出力項目は未確認**。実装の最初の作業として公式ページで確定させる（この環境からは公式ページに接続できないため） |
| 通常価格とセール価格 | API の `itemPrice` は「取得時点の販売価格」として扱う。通常価格は、ブランド公式（希望小売価格・公式ストア価格）か販売ページの表示から取る。セール期間は、イベントの公式告知から取る。すべての値に URL と取得日時を記録する |
| ブランド公式サイト | Claude が商品ページを読み、スペックを記録する（少量の閲読に限り、一括収集はしない） |
| Amazon | 自動取得はしない（PA-API は終了済み、後継の Creators API は販売実績が条件、利用規約がロボットによる収集を禁止）。あなたが確認した価格を、手入力用の CSV で取り込む（半自動） |
| セールの時期 | 楽天スーパーSALE・お買い物マラソン・Qoo10メガ割・Amazon の大型セールを、実行のたびに公式告知で確認し、`research/calendar.json` に出典つきで記録する |
| トレンド | Web 検索で、テーマ・切り口を出典つきで要約する。デザイン（トークン・テンプレート・世界観）には反映しない |
| 競合の記録 | 手入力の記録表 `research/competitors/log.csv`。あなたがアプリで見た公開投稿の URL と本文を貼ると、Claude が「型」（テーマ・構成・見出しの作り方）を分類して記録する。自動収集はしない |
| 表現のチェック | 薬機法・景表法の NG 表現と、使用感を示す表現（使ってみた・愛用・〜年使って・リピ など）をエラーにする。あわせて、数値に出典があるか、セール期限が切れていないか、PR表記があるかを検査する |
| 認証情報 | `.env`（Git の管理対象外）と `.env.example`。コードには書かない |

## 2. ワークフロー（承認を省略できない作り）

```
① /research [テーマ]          調査 → research/runs/<実行ID>/ideas.md（投稿案リスト）
② npm run research:approve -- <実行ID> <案ID…>   あなたのコマンドで承認記録（approval.json）を残す
③ /research-draft <案ID>       承認記録がない案は生成を拒否 → 原稿 JSON / CSV / キャプション案 → 検証・表現チェック
④ npm run build                既存エンジンで描画（手動）
```

- 「調査から描画まで一気に実行するモード」は作らない。
- 定期実行（週1回など）に拡張しても、実行するのは①だけ。

**投稿案リストの列**：ID ／ テーマ ／ 対象商品（価格と取得日時） ／ A案かB案か ／ 表紙の英単語案 ／ 見出し案（A：リード、B：リール見出し） ／ 推奨投稿タイミング（セール連動など） ／ 根拠と出典

**カテゴリの優先順**：美顔器 → ヘアケア家電（ドライヤー・ヘアアイロン） → 電動洗顔ブラシ → スチーマー → 脱毛器
